## What would fix it

**Minimum**

- x86-64, 4 cores or better
- 16 GB RAM (8 GB is workable, 16 GB removes the ceiling)
- NVMe SSD, 256 GB or larger
- Runs Linux with no out-of-tree driver fights

**Helpful**

- 32 GB RAM (local Android emulator + Rust release builds at the same time)
- USB-C with DisplayPort alt mode
- User-replaceable battery and SSD

_Not asking for the newest or the fastest. Refurbished, previous-generation, or review-unit hardware all do the job._

## How this is being built right now

Nothing above was built on a laptop. The desktop comes from [Linux-For-Android](https://github.com/pdev-labs/Linux-For-Android), a full Linux environment running on Android with no root. When something needs a real GUI session, it runs inside a GitHub Actions runner provisioned by [Free-Github-Actions-RDP](https://github.com/pdev-labs/Free-Github-Actions-RDP-for-App-Testing). Both are my own projects, so the workaround is part of the portfolio rather than an excuse.

## What I give back

1. **Named credit in the repositories.** Whoever provides the machine is credited by name in the README of every repository it unblocks, and at the top of the build log. Not a temporary banner that quietly disappears — it stays there.
2. **A public build log.** What shipped each week, what broke, and how long each build took — on the actual hardware.
3. **A written Linux compatibility report.** What worked out of the box, what needed a quirk, and what I would tell the next person who buys it. Published in full, with attribution, and nobody gets to edit it first.
4. **Upstream fixes.** Every driver quirk, packaging bug and kernel problem I hit turns into a patch or a bug report rather than a tweet.
5. **It stays in circulation.** If the machine is replaced later, it goes to another maintainer, not into a drawer.

## Scope
